# Vercel

## Overview

Vercel adalah platform deployment frontend yang dirancang khusus untuk framework modern seperti **Next.js**, dengan fokus pada kecepatan build, preview environment, dan workflow berbasis Git.

Dalam praktiknya, Vercel lebih tepat diposisikan sebagai **layer deployment frontend + CI/CD terintegrasi**, bukan sebagai pengganti server tradisional atau platform backend umum.

---

## Use Cases

Berdasarkan penggunaan personal dan konteks teknis, Vercel relevan untuk:

- Deployment **Next.js (App Router maupun Pages Router)** tanpa konfigurasi server
- Preview otomatis untuk setiap **pull request**
- Hosting blog statis berbasis **MDX / Contentlayer**
- Validasi routing, SEO, dan build sebelum production
- Proof-of-concept atau MVP frontend dengan iterasi cepat

Vercel paling efektif pada fase **eksplorasi, validasi arsitektur, dan pengembangan iteratif**.

---

## Strength

Beberapa kekuatan yang terasa signifikan dalam praktik:

- Integrasi **native** dengan Next.js
- Zero-configuration deployment
- Preview environment otomatis per branch / PR
- Build, rollback, dan redeploy cepat
- Dukungan edge & serverless tanpa setup manual

Dalam konteks developer experience, Vercel membantu **mengurangi beban operasional**, sehingga fokus dapat langsung diarahkan ke kode dan konten.

---

## Limitation

Batasan yang perlu disadari sejak awal:

- Kontrol server dan runtime sangat terbatas
- Kurang cocok untuk backend kompleks atau stateful
- Biaya dapat meningkat seiring traffic dan frekuensi build
- Tidak ideal untuk kebutuhan compliance ketat (on-prem, audit, isolasi jaringan)

Vercel **bukan pengganti server tradisional**, dan tidak ditujukan untuk sistem operasional atau industri kritikal.

---

## Alternatif

Tergantung konteks dan kebutuhan, beberapa alternatif yang sering dipertimbangkan:

- **Netlify** — pendekatan serupa untuk static site & frontend
- **Cloudflare Pages** — fokus edge & performance global
- **GitHub Pages** — static sederhana dengan kontrol minimal
- **Self-hosted (VPS / container)** — kontrol penuh dengan beban operasional lebih tinggi

Pemilihan platform sebaiknya didasarkan pada **konteks teknis dan risiko**, bukan popularitas.
